# Embedding (임베딩)

**Embedding은 단어, 이미지 등의 데이터를 모델이 활용할 수 있는 숫자 벡터로 표현하는 것입니다.** 벡터는 숫자를 순서대로 모은 것이며, 학습을 통해 데이터의 특징과 관계를 담도록 만들 수 있습니다.

### 1. 왜 필요한가요?

모델은 단어 자체를 직접 계산할 수 없으므로 숫자 표현이 필요합니다. 단어에 번호만 붙이면 번호 사이의 크기나 차이가 의미를 나타내지는 않습니다. 임베딩은 각 토큰을 여러 숫자로 표현하고, 학습 목적에 필요한 관계를 벡터에 반영할 수 있게 합니다.

```text
토큰 → 토큰 ID → 임베딩 벡터
고양이 → 12 → [0.2, -0.5, 0.8, ...]
강아지 → 35 → [0.3, -0.4, 0.7, ...]
```

위 숫자는 설명용 예시입니다. 실제 벡터는 학습으로 정해지며, 비슷한 의미나 사용 맥락의 토큰이 가까운 벡터를 갖도록 학습될 수 있습니다. 각 숫자에 사람이 미리 의미를 붙이는 것은 아닙니다.

### 2. PyTorch 코드로 보기

```python
embedding = nn.Embedding(num_embeddings=10000, embedding_dim=64)
# 토큰 ID 10,000개 각각에 대응하는 64차원 벡터를 관리
# 벡터 값은 모델 파라미터이며 학습 과정에서 업데이트됨

vectors = embedding(token_ids)
# token_ids: (배치 크기, 토큰 수), 정수형 텐서
# vectors: (배치 크기, 토큰 수, 64)
```

### 3. 문맥 및 Hidden State와의 차이

- **기본 토큰 임베딩**: 같은 토큰 ID에는 같은 벡터를 제공합니다. 이 단계만으로는 주변 문맥에 따라 값이 달라지지 않습니다.
- **문맥(Context)**: 주변 단어나 앞뒤 내용처럼 의미를 해석하는 데 필요한 정보입니다. 예를 들어 ‘먹는 배’와 ‘타는 배’는 문맥에 따라 뜻이 달라집니다.
- **문맥을 반영한 표현**: 임베딩을 RNN이나 Transformer 등으로 처리하면 주변 정보가 반영된 표현을 만들 수 있습니다.
- **Hidden state**: 모델 내부에서 계산되는 중간 상태입니다. RNN에서는 현재 입력과 이전 상태를 반영합니다. 입력 임베딩과는 역할이 다릅니다.

전력값처럼 이미 숫자인 데이터는 반드시 토큰 임베딩을 거칠 필요는 없습니다. 앞의 전력 예측 실습에서는 표준화한 전력값을 LSTM에 직접 입력합니다. StandardScaler는 평균과 표준편차로 단위를 맞추는 도구이며, 학습되는 임베딩과는 다릅니다.

> 기억할 문장: 임베딩은 데이터를 모델이 활용할 수 있는 숫자 벡터로 표현하는 것입니다.
